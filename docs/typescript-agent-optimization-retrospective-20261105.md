后端入口从 Python 切换为 `node dist/cli.js`，本地实验脚本切换到 TypeScript CLI；Java 插件、DevEco/OpenCode 接入沿用各自的桥接层。以下能力在合入时已经存在，后续主要补边界与正确性：

合入前的 `098efee`、`4d0e709` 是上述异味约束、模型策略和集中材料的重要来源。不能把“文件在 TypeScript 后端中存在”理解成它是在 11 月新实现的。

## 4. 迁移后的主要修复

### 4.1 保留评审语义，减少纯格式返工

问题有两类：评审已经指出语义缺陷，但格式重试后的调度没有正确保留该失败；以及模型在唯一 JSON 前后添加说明，导致平台把有效评审判作格式错误。

调整包括：

- `03377da`：格式修复后继续按原评审语义处理，不能因为格式修复子进程退出成功就把语义 FAIL 当作 PASS。
- `e52363b`：允许最终回复中的唯一完整评审对象被说明文字或代码围栏包围。拒绝重复字段、多个对象、数组/嵌套包装、截断对象及不自洽结论。
- JSONL 只从最终文本消息提取评审，不借用工具输出或前一轮结果。
- 仅格式修复不允许重做评审或修改结论；证据不足继续 BLOCKED/UNCERTAIN。

实现：`src/review_output.ts`、`src/runner.ts`；验证：`tests/review_output.test.ts`、`tests/review_entry.test.ts`、`tests/runner.test.ts`。

### 4.2 恢复 Agent 必要自检，并在成功后及时交回

按用户反馈，撤销过“Agent 不做验证、全部交给工具链”的实验设置。`16e2993` 恢复重构和返修的必要内部检查，保留平台独立门禁。

随后针对“检查已经通过，仍继续解释、读文件或再构建”增加收尾机制：

- `3a4ba50`：引入 `ARKTS_FINAL_CHECK` 标记，结合本会话真实工具完成事件，在全部已观察编辑后完成验证时交回。
- `253d035`：允许同一步中同时完成只读查询，避免把无害的伴随读取误判为不能交回。
- `6289f9d`：成功但未带标记的验证不会清空编辑状态，使后续显式收尾仍有机会成立。
- 失败检查、未完成工具、其他会话或编辑后未覆盖的新检查不能触发成功交回。

实现：`src/validation_handoff.ts`、`src/agent_runtime.ts`、`src/process.ts`。这是一套基于实际事件的交接条件，不是省略必要验证，也不会将内部失败改写成成功。

### 4.3 Code Clone 同宿主定位与抽取指导

此前仅给出两段克隆行号，模型常重复探索抽取位置，或依据检测器的 `different classes` 文本误判实际宿主。

- `f028316`：在 Code Clone 专属分析器内定位两个实例的真实 class/struct 和成员，提供共享行、差异行、调用位置及候选抽取方式。
- `8a6af7e`：支持范围从成员之前的空行或装饰器开始。
- `6608b04`：范围只覆盖装饰器、尚未进入成员时不能据此声称成员已定位。
- 提示优先沿用同宿主，保留入口、this、状态所有权、UI ID 和事件时机；不依靠全库搜索决定一个局部抽取。

实现：`src/analysis/code_clone.ts`；验证：`tests/clone_evidence.test.ts`。

### 4.4 测试计划冻结及克隆组覆盖

主线合入提供了按原接口和测试导入/调用关系选择测试的基础。后续 `237a0db` 修复克隆组只保留一个成员覆盖、遗漏设备场景的问题：

- 重构前冻结原文件、所属类/组件、方法、签名和已注册测试关系。
- 同组多个成员均参与选择；同一 suite 内仍完整运行。

### 4.5 响应式读取证据与抽取后风险检查

`1de5c77` 在 Code Clone 专属分析器中补充宿主状态声明、装饰器、读取/写入线索及 ForEach/LazyForEach 数据源，区分宿主字段与成员形参。其目的是让 Agent 快速找到真实依赖，不能用“没有搜到写入”推断普通值传参安全。

第 24 条曾把 `this.departure/this.destination` 改为 Builder 的普通 `value: string` 形参，交换城市、清空城市后的显示测试失败。`3b3e937` 进一步：

- 明确建议传递静态分支标识，在同宿主 Builder 内直接读取响应式字段。
- 比较原/当前快照，定位新增的响应式字段到 Builder 普通 string/number/boolean 参数传递。
- 将字段、参数、前后行号和修复方向写入 `reactive-extraction.json`；相关测试失败时内嵌给返修，门禁通过时提供给评审。
- 每轮重新计算，避免修复后遗留上一轮诊断。

实现：`src/analysis/clone_reactivity.ts`、`src/analysis/builder_state.ts`、`src/reactive_evidence.ts`。词法命中是风险线索，不单独判 FAIL；未命中同样不证明等价。

## 6. 本轮发现但尚未完成的优化

### 6.1 返修应对照原实现，不应根据测试标题改业务规则

Instrument 27 首轮 Local 18/18 通过；设备测试 24/25 通过，失败实际断言是选择 1:1 后 `boundsChanged(before, rect)`，而不是宽高比断言。

首次抽取 helper 展开后，两段原计算逻辑的规范化文本相同，这只能证明抽取文本关系，不能证明设备行为完全等价。但返修 Agent 没有这样的前后对照，依据测试名称猜测“裁剪后必须再次等比收缩”，新增原先不存在的规则。随后 Local 从 18/18 变成 17/18，失败从设备转为稳定的本地数值断言；后两轮还误读了 `expect 70 equals 120` 的实际/期望方向。

待改方向：返修提示提供原/当前生产代码差异、断言方向、此前已通过门禁及新增回归；要求先证明改动与失败相关，避免将测试标题或自然语言猜测当成新需求。是否增加有界的基线对照/原样重放，先通过本地诊断确认，不先把失败自动放行。

### 6.2 循环抽取必须保留异常时的部分结果

两条 Local CartPageLogic 都把 try 内逐项 `push` 改为 helper 构建完整数组后再返回。第一条使用 `push(...helper())`，虽然保留外层数组对象，却仍要等 helper 完成后才会 push；第二条直接整体赋值。

在循环中途抛错时，原实现的 catch 后可保留此前已追加的数据；新实现的外层数组仍为空。用保存的 update/helper 方法做离线故障注入，令第二张卡片为 null：两条原实现均保留第一张卡片，新实现均得到空列表；正常两张卡片输入的结果一致。该诊断不是设备测试，也不证明真实服务会返回 null；它证明评审不能仅凭正常路径测试通过，就断言已有 catch 的部分结果语义不变。实际 `resolveUri` 会自行捕获异常，不能把它误写为已证实的外抛来源。

待改方向：在 Code Clone 专属分析器提供 try/catch、外部累加数组和逐项提交位置；优先保留原循环和 push，只抽单项构建，或让 helper 写入原累加器并保持时机。评审应核对异常路径，而不只比较最终正常值。

### 6.3 Local 1 的耗时与同名测试选择

Local 1 总耗时 427.913 秒，超过目标 7.913 秒。Agent 用时 205.431 秒；内部 check 事件到后续 build 事件之间约 112.5 秒，两次工具本身分别约 1.7 秒、2.2 秒。这是模型交互间隔，日志无法将它全部拆成推理时间或服务等待时间。

两条 Local 的计划还都选择了不同模块的两个同名 CartPageLogicTest。当前 sourceInterface 对箭头函数属性入口的识别不足，回退到了同名选择。待补原箭头成员和间接调用的正向关联证据后再精确选择；不能为了提速直接删掉一个测试作业。
